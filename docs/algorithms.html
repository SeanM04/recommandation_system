The interface

Two methods. rank(context, candidates, n) returns up to n of the offers this customer is eligible for, best first, each with the score it was ranked by. update(context, offer_id, reward) takes one reward between 0 and 1. Policies hold no state of their own: what they know lives in the options store, so a restart or a second API worker sees the same model.

What a policy knows

One ArmStats per offer and context key: how many rewards it has seen and their sum. The Beta belief that Thompson sampling uses is derived from those two numbers, so they can never disagree.

@dataclass(frozen=True)
class ArmStats:
    """What a policy knows about one offer in one context.

    ``pulls`` counts the rewards seen and ``total_reward`` sums them. With forgetting
    switched on both shrink over time, so ``pulls`` is an *effective* count, not an
    integer. The Beta belief follows from them, so it can never disagree with them.
    """

    pulls: float = 0.0
    total_reward: float = 0.0

    @property
    def alpha(self) -> float:
        return PRIOR_ALPHA + self.total_reward

    @property
    def beta(self) -> float:
        return PRIOR_BETA + self.pulls - self.total_reward

    @property
    def mean(self) -> float:
        """Posterior mean take-up rate: alpha / (alpha + beta)."""
        return self.alpha / (self.alpha + self.beta)

    def updated(self, reward: float) -> ArmStats:
        """Add one reward in [0, 1]: alpha += reward, beta += 1 - reward."""
        return ArmStats(self.pulls + 1, self.total_reward + reward)

    def decayed(self, gamma: float) -> ArmStats:
        """Forget: shrink the evidence by ``gamma`` towards the Beta(1, 1) prior."""
        return ArmStats(self.pulls * gamma, self.total_reward * gamma)

Thompson sampling

Draw one plausible take-up rate from each offer's belief and rank by the draws. A well-known offer draws close to its true rate every time; an offer with little evidence draws widely, so now and then it wins a slot and gets tested. Exploration is driven by uncertainty, with no rate to tune.

class ThompsonSamplingPolicy(BanditPolicy):
    """Keep a Beta(alpha, beta) belief about each offer's take-up rate, draw one
    plausible rate from every belief, and rank the offers by their draws.

    An offer we know little about has a wide belief, so it sometimes draws high and
    gets shown: exploration happens in proportion to uncertainty, with nothing to tune.
    """

    def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
        check_slate_size(n)
        stats = self.stats(context, candidates)
        draws = {
            offer_id: float(self.rng.beta(arm.alpha, arm.beta)) for offer_id, arm in stats.items()
        }
        best = sorted(draws, key=draws.get, reverse=True)[:n]
        return [ScoredOffer(offer_id, draws[offer_id]) for offer_id in best]

Epsilon-greedy

Mostly show the offers with the best average so far; with probability ε a slot goes to a random offer instead. Simple and predictable, but it explores blindly: it spends as much on offers it already knows are poor as on offers it knows nothing about.

def current_epsilon(self, stats: dict[str, ArmStats]) -> float:
    evidence = sum(arm.pulls for arm in stats.values())
    return max(self.min_epsilon, self.epsilon * self.epsilon_decay**evidence)

@staticmethod
def estimate(arm: ArmStats) -> float:
    return arm.total_reward / arm.pulls if arm.pulls > 0 else UNTRIED_SCORE

def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
    check_slate_size(n)
    stats = self.stats(context, candidates)
    epsilon = self.current_epsilon(stats)
    estimates = {offer_id: self.estimate(arm) for offer_id, arm in stats.items()}

    # Shuffle, then sort best first: offers with equal estimates end up in random order.
    offer_ids = list(estimates)
    shuffled = [offer_ids[i] for i in self.rng.permutation(len(offer_ids))]
    remaining = sorted(shuffled, key=estimates.get, reverse=True)

    ranked = []
    while remaining and len(ranked) < n:
        if self.rng.random() < epsilon:
            pick = remaining[self.rng.integers(len(remaining))]  # explore
        else:
            pick = remaining[0]  # exploit
        remaining.remove(pick)
        ranked.append(ScoredOffer(pick, estimates[pick]))
    return ranked

Learning and forgetting

Built

Both bandits share one update, and the store performs it atomically. With forgetting switched on, every offer in the context first loses a sliver of its evidence, then the new reward is added. Old evidence fades, so a change in behaviour shows through within a few thousand responses instead of being outvoted by months of history. The update-rule tree shows the same flow as a diagram.

def update(self, context: Context, offer_id: str, reward: float) -> None:
    """Forget a little (if decay is on), then add the new evidence.

    The store does both in one atomic step, so concurrent requests never overwrite
    each other's learning.
    """
    if not 0 <= reward <= 1:
        raise ValueError(f"reward must be in [0, 1], got {reward}")
    self.store.learn(self.name, self.key(context), offer_id, reward, decay=self.decay)

def learn(
    self, policy: str, context_key: str, offer_id: str, reward: float, decay: float = 1.0
) -> None:
    now = datetime.now(UTC)
    with self._lock:
        rows = self._rows.setdefault((policy, context_key), {})
        if decay < 1:
            for other, (stats, _) in list(rows.items()):
                rows[other] = (stats.decayed(decay), now)
        stats, _ = rows.get(offer_id, (ArmStats(), now))
        rows[offer_id] = (stats.updated(reward), now)

def learn(
    self, policy: str, context_key: str, offer_id: str, reward: float, decay: float = 1.0
) -> None:
    now = datetime.now(UTC)
    forget = (
        update(options)
        .where(options.c.policy == policy, options.c.context_key == context_key)
        .values(
            pulls=options.c.pulls * decay,
            total_reward=options.c.total_reward * decay,
            updated_at=now,
        )
    )
    add = (
        self._insert()
        .values(
            policy=policy,
            context_key=context_key,
            offer_id=offer_id,
            pulls=1.0,
            total_reward=reward,
            updated_at=now,
        )
        .on_conflict_do_update(
            index_elements=KEY_COLUMNS,
            set_={
                "pulls": options.c.pulls + 1.0,
                "total_reward": options.c.total_reward + reward,
                "updated_at": now,
            },
        )
    )
    # One transaction. Each statement computes from the row's current value inside
    # the database, so two requests running at once cannot overwrite each other.
    with self.engine.begin() as connection:
        if decay < 1:
            connection.execute(forget)
        connection.execute(add)

Why the default is γ = 0.9998. Forgetting matters little for a new hit offer, because Thompson sampling keeps testing offers it has rarely shown. It matters a lot when an offer the model is confident about changes. Over 5 seeds, after families' favourite switched, the policy without forgetting ranked the new favourite first in 15% of their app opens; at γ = 0.9998 it was 74%. make experiment reruns it; full numbers are in decision P9.

Baselines

Two policies that never learn online set the bar. Random shows offers in random order: the floor. Static is the batch-trained model a bank or telco often runs today: one popularity table fitted from a historical log, the same for every customer, frozen until the next retrain.

@classmethod
def fit(cls, history: Iterable[tuple[str, float]], name: str = "static") -> StaticPolicy:
    """The batch training job: average reward per offer over a log of (offer_id, reward)."""
    totals: dict[str, float] = defaultdict(float)
    counts: dict[str, int] = defaultdict(int)
    for offer_id, reward in history:
        totals[offer_id] += reward
        counts[offer_id] += 1
    return cls({offer_id: totals[offer_id] / counts[offer_id] for offer_id in counts}, name)

def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
    check_slate_size(n)
    scores = {offer.offer_id: self.popularity.get(offer.offer_id, 0.0) for offer in candidates}
    best = sorted(scores, key=scores.get, reverse=True)[:n]  # stable: ties keep catalogue order
    return [ScoredOffer(offer_id, scores[offer_id]) for offer_id in best]
