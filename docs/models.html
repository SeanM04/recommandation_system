Policies & models

Every policy, one by one

Ten policies decide which three offers each customer sees. They are built from five ideas: learning online, personalising by segment, exploring by doubt, forgetting, and learning from customer features. Each adds a single idea to another, so comparing them shows what each idea is worth. This page shows how they relate, how each ranks and learns (with the code that runs, copied from the source when the docs are built), and how each did.

The interface

Two methods. rank(context, candidates, n) returns up to n of the offers this customer is eligible for, best first, each with the score it was ranked by. update(context, offer_id, reward) takes one reward between 0 and 1. The Beta policies hold no state of their own: what they know lives in the options store, so a restart or a second API worker sees the same model. The feature model keeps its matrices in memory, which is why it runs in the simulator only.

How each kind decides and learns

There are five kinds of model. The variants of each differ only in configuration, so the same flow applies to all of them.

The baselines: random offers and the fixed popularity ranking

@classmethod
def fit(cls, history: Iterable[tuple[str, float]], name: str = "static") -> StaticPolicy:
    """The batch training job: average reward per offer over a log of (offer_id, reward)."""
    totals: dict[str, float] = defaultdict(float)
    counts: dict[str, int] = defaultdict(int)
    for offer_id, reward in history:
        totals[offer_id] += reward
        counts[offer_id] += 1
    return cls({offer_id: totals[offer_id] / counts[offer_id] for offer_id in counts}, name)

def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
    """The eligible offers by popularity, the same order for every customer."""
    check_slate_size(n)
    scores = {offer.offer_id: self.popularity.get(offer.offer_id, 0.0) for offer in candidates}
    # sorted() is stable: offers with equal popularity keep catalogue order.
    best = sorted(scores, key=scores.__getitem__, reverse=True)[:n]
    return [ScoredOffer(offer_id, scores[offer_id]) for offer_id in best]

Epsilon-greedy: exploit the best average, explore a fixed share of the time

def current_epsilon(self, stats: dict[str, ArmStats]) -> float:
    """The exploration rate now: epsilon, shrunk by the evidence so far if decay is set."""
    evidence = sum(arm.pulls for arm in stats.values())
    return max(self.min_epsilon, self.epsilon * self.epsilon_decay**evidence)

@staticmethod
def estimate(arm: ArmStats) -> float:
    """An offer's average reward so far; one never shown scores 1.0 so it gets tried."""
    return arm.total_reward / arm.pulls if arm.pulls > 0 else UNTRIED_SCORE

def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
    """Fill each slot with the best remaining average, or a random offer epsilon of the time."""
    check_slate_size(n)
    stats = self.stats(context, candidates)
    epsilon = self.current_epsilon(stats)
    estimates = {offer_id: self.estimate(arm) for offer_id, arm in stats.items()}

    # Shuffle, then sort best first: offers with equal estimates end up in random order.
    offer_ids = list(estimates)
    shuffled = [offer_ids[i] for i in self.rng.permutation(len(offer_ids))]
    remaining = sorted(shuffled, key=estimates.__getitem__, reverse=True)

    ranked: list[ScoredOffer] = []
    while remaining and len(ranked) < n:
        if self.rng.random() < epsilon:
            pick = remaining[self.rng.integers(len(remaining))]  # explore
        else:
            pick = remaining[0]  # exploit
        remaining.remove(pick)
        ranked.append(ScoredOffer(pick, estimates[pick]))
    return ranked

Thompson sampling: explore in proportion to doubt

class ThompsonSamplingPolicy(BanditPolicy):
    """Keep a Beta(alpha, beta) belief about each offer's take-up rate, draw one
    plausible rate from every belief, and rank the offers by their draws.

    An offer we know little about has a wide belief, so it sometimes draws high and
    gets shown: exploration happens in proportion to uncertainty, with nothing to tune.
    """

    def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
        """Draw a take-up rate from each offer's Beta belief and show the highest draws."""
        check_slate_size(n)
        stats = self.stats(context, candidates)
        draws = {
            offer_id: float(self.rng.beta(arm.alpha, arm.beta)) for offer_id, arm in stats.items()
        }
        best = sorted(draws, key=draws.__getitem__, reverse=True)[:n]
        return [ScoredOffer(offer_id, draws[offer_id]) for offer_id in best]

What a Beta policy knows: one ArmStats per offer and context key, how many rewards it has seen and their sum. The Beta belief is derived from those two numbers, so they can never disagree.

@dataclass(frozen=True)
class ArmStats:
    """What a policy knows about one offer in one context.

    ``pulls`` counts the rewards seen and ``total_reward`` sums them. With forgetting
    switched on both shrink over time, so ``pulls`` is an *effective* count, not an
    integer. The Beta belief follows from them, so it can never disagree with them.
    """

    pulls: float = 0.0
    total_reward: float = 0.0

    @property
    def alpha(self) -> float:
        """The Beta belief's alpha: the prior plus the rewards seen."""
        return PRIOR_ALPHA + self.total_reward

    @property
    def beta(self) -> float:
        """The Beta belief's beta: the prior plus the responses that earned nothing."""
        return PRIOR_BETA + self.pulls - self.total_reward

    @property
    def mean(self) -> float:
        """Posterior mean take-up rate: alpha / (alpha + beta)."""
        return self.alpha / (self.alpha + self.beta)

    def updated(self, reward: float) -> ArmStats:
        """Add one reward in [0, 1]: alpha += reward, beta += 1 - reward."""
        return ArmStats(self.pulls + 1, self.total_reward + reward)

    def decayed(self, gamma: float) -> ArmStats:
        """Forget: shrink the evidence by ``gamma`` towards the Beta(1, 1) prior."""
        return ArmStats(self.pulls * gamma, self.total_reward * gamma)

Thompson sampling on customer features: the step beyond segments

def rank(self, context: Context, candidates: Sequence[Offer], n: int) -> list[ScoredOffer]:
    """Draw a weight vector per offer from its posterior; rank by predicted take-up."""
    check_slate_size(n)
    ids = [offer.offer_id for offer in candidates]
    rows = self._rows(ids)
    x = features(context)
    precision = self._evidence[rows] + self.prior * np.eye(len(FEATURES))
    mean = np.linalg.solve(precision, self._targets[rows][..., None])[..., 0]
    lower = np.linalg.cholesky(precision)  # precision = L L^T, so cov = L^-T L^-1
    noise = self.rng.standard_normal(mean.shape)
    spread = np.linalg.solve(np.swapaxes(lower, 1, 2), noise[..., None])[..., 0]
    scores = (mean + self.scale * spread) @ x
    best = np.argsort(-scores)[:n]
    return [ScoredOffer(ids[i], float(scores[i])) for i in best]

def update(self, context: Context, offer_id: str, reward: float) -> None:
    """Forget a little across every offer (if decay is on), then add this response."""
    if not 0 <= reward <= 1:
        raise ValueError(f"reward must be in [0, 1], got {reward}")
    (row,) = self._rows([offer_id])
    if self.decay < 1:
        self._evidence *= self.decay
        self._targets *= self.decay
    x = features(context)
    self._evidence[row] += np.outer(x, x)
    self._targets[row] += reward * x

Learning and forgetting

Built

The Beta policies share one update, and the store performs it atomically. With forgetting switched on, every offer in the context first loses a sliver of its evidence, then the new reward is added. Old evidence fades, so a change in behaviour shows through within a few thousand responses instead of being outvoted by months of history. The update-rule tree shows the same flow as a diagram.

def update(self, context: Context, offer_id: str, reward: float) -> None:
    """Forget a little (if decay is on), then add the new evidence.

    The store does both in one atomic step, so concurrent requests never overwrite
    each other's learning.
    """
    if not 0 <= reward <= 1:
        raise ValueError(f"reward must be in [0, 1], got {reward}")
    self.store.learn(self.name, self.key(context), offer_id, reward, decay=self.decay)

def learn(
    self, policy: str, context_key: str, offer_id: str, reward: float, decay: float = 1.0
) -> None:
    """Forget a little across the context (if decay is on), then add one reward."""
    now = datetime.now(UTC)
    with self._lock:
        rows = self._rows.setdefault((policy, context_key), {})
        if decay < 1:
            for other, (stats, _) in list(rows.items()):
                rows[other] = (stats.decayed(decay), now)
        stats, _ = rows.get(offer_id, (ArmStats(), now))
        rows[offer_id] = (stats.updated(reward), now)

src/recommender/store/options_store.py

def learn(
    self, policy: str, context_key: str, offer_id: str, reward: float, decay: float = 1.0
) -> None:
    """Forget a little across the context (if decay is on), then add one reward, atomically."""
    now = datetime.now(UTC)
    forget = (
        update(options)
        .where(options.c.policy == policy, options.c.context_key == context_key)
        .values(
            pulls=options.c.pulls * decay,
            total_reward=options.c.total_reward * decay,
            updated_at=now,
        )
    )
    add = (
        self._insert()
        .values(
            policy=policy,
            context_key=context_key,
            offer_id=offer_id,
            pulls=1.0,
            total_reward=reward,
            updated_at=now,
        )
        .on_conflict_do_update(
            index_elements=KEY_COLUMNS,
            set_={
                "pulls": options.c.pulls + 1.0,
                "total_reward": options.c.total_reward + reward,
                "updated_at": now,
            },
        )
    )
    # One transaction. Each statement computes from the row's current value inside
    # the database, so two requests running at once cannot overwrite each other.
    with self.engine.begin() as connection:
        if decay < 1:
            if connection.dialect.name == "postgresql":
                # Forgetting locks every row in the context. Two requests locking them in
                # different orders deadlock (seen with 4 workers), so updates to one
                # context queue on a lock of their own first. SQLite locks the whole file.
                connection.execute(
                    select(
                        func.pg_advisory_xact_lock(
                            func.hashtext(policy), func.hashtext(context_key)
                        )
                    )
                )
            connection.execute(forget)
        connection.execute(add)

Why the default is γ = 0.9998. Forgetting matters little for a new hit offer, because Thompson sampling keeps testing offers it has rarely shown. It matters a lot when an offer the model is confident about changes. Over 5 seeds, after families' favourite switched, the policy without forgetting ranked the new favourite first in 15% of their app opens; at γ = 0.9998 it was 74%. make experiment reruns it; full numbers are in decision P9.

Thompson on customer features thompson_features

The idea
Thompson sampling on customer features instead of segments: a Bayesian linear model of each offer's take-up over about 20 features.
How it ranks
Draws one set of weights per offer from its posterior and scores the customer's features with them; shows the three highest scores.

How they are used here

  1. Serving. Every app open is ranked by the policy named in recommendation.active_policy in settings.yaml. Any request can ask for another with ?policy=, which is how an A/B test or a holdout would run. Each Beta policy keeps its own beliefs in the options store, so they can all learn side by side. The feature model can't serve yet; asked for by name, the API says so.
  2. Learning. POST /response looks up which policy served the app open, turns the outcome into that policy's reward, and updates its belief in one database transaction.
  3. Comparing. The simulator runs every policy on the identical 50,000 app opens, 10 times with different seeds, against the oracle, and the sensitivity sweep reruns the key ones in five other versions of the world. The Results page and the dashboard read what they save.
  4. Explaining. The dashboard's stories cast four of them: the serving policy as the learner, the fixed popularity ranking as the baseline, Thompson per segment as the learner without forgetting, and epsilon-greedy per segment as the explorer that never stops.
